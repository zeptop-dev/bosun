# Subscription node connection IP version

Available in the shared `pkg/subscription` library from bosun v0.93.0, and used
by Captain v1.59.0. `Line.IPVersion` selects the client connection family for the
published `Host`. It does not change a server listener, server egress, DNS
records, geolocation, or intermediate hops of a server-managed forwarding line.
Existing managed agents need no new state fields or runtime behavior. The
standalone panel keeps its existing subscription controls; this release does
not add a per-node IP policy editor there.

**中文说明：** 这是订阅节点的客户端连接策略。IPv4 / IPv6 模式只允许对应
地址族，失败时不回落到另一地址族；双栈允许两者，但实际选择和是否并发竞争
取决于客户端及协议。空值保留历史输出。域名仍以域名发布，不会被替换成某次
解析的 IP；DNS、监听、防火墙和客户端网络仍须实际支持选定地址族。

## Policy and validation

| `Line.IPVersion` | Meaning |
| --- | --- |
| Empty string | Preserve legacy client/template behavior and raw `Extra` fields. |
| `ipv4` | Use IPv4 only; do not fall back to IPv6. |
| `ipv6` | Use IPv6 only; do not fall back to IPv4. |
| `dual` | Permit both families using the client's native selection behavior. |

Dual stack requires a hostname. A literal address must match the selected family;
IPv4-mapped literals are normalized to IPv4. Scoped addresses and malformed
connection hosts are rejected. No DNS query is performed during validation.

With a typed policy selected, conflicting raw `Extra` fields for IP selection,
resolvers, endpoint replacement and proxy detours are rejected. The empty policy
keeps those legacy fields intact. Callers must validate input before saving and
check format support before presenting a policy as usable.

## Client output

The normal protocol/transport support matrix still applies. A family selector
does not add support for a protocol that a renderer already omits.

| Format | Strict hostname `ipv4` / `ipv6` | Hostname `dual` |
| --- | --- | --- |
| Mihomo / Clash Meta | Per-proxy `ip-version: ipv4` / `ipv6` | `ip-version: dual` |
| sing-box 1.12+ | Per-outbound `domain_resolver` with `ipv4_only` / `ipv6_only` | Native resolver default, without a strict family strategy |
| Surge | Per-proxy `ip-version=v4-only` / `v6-only` | `ip-version=dual` |
| Stash, Surfboard, Loon, Quantumult X, Egern, URI lists and other formats | Omit the entry when no verified family selector exists | Preserve the hostname and use client settings |

Matching fixed-IP endpoints can be rendered without a hostname-family selector,
subject to each format's protocol support. A share URI must not silently weaken
a strict hostname policy into an unrestricted connection.

For Mihomo and Surge, an emitted IPv6 or dual entry needs global IPv6 admission.
An absent setting is enabled; an explicit incompatible setting returns
`ErrIPVersionTemplateConflict`. Entries omitted by the protocol renderer do not
affect global flags. This does not enable TUN, rewrite client-facing DNS AAAA
policy, or enable the separate concurrent-dialer enhancement.

ShadowTLS carries the policy on its address-bearing transport outbound in
sing-box, rather than on the inner protocol outbound. A dependent client-chain
destination may be resolved by an upstream proxy, so Captain restricts the
typed policy to directly connected front nodes and filters incompatible chains.

## WireGuard boundary

WireGuard hostnames retain automatic behavior. A matching literal peer endpoint
can use a strict family without adding a selector, but a hostname with `ipv4`
or `ipv6` is unsupported. Mihomo's field can also change tunneled target DNS;
the current sing-box WireGuard output uses separate endpoint resolution. Neither
is treated as a verified endpoint-only selector. Dual stack does not create a
second peer, change keys or promise parallel WireGuard handshakes.

## Compatibility and verification

The new field is additive to the shared Go subscription model; it is not a new
agent-state requirement. Empty values preserve old rendering. Managed Captain
subscriptions are generated by the panel, so upgrading only a node's bosun
binary does not enable this setting. Older panels ignore the saved policy;
Captain v1.59.0 defines the corresponding panel rollback boundary.

Unit tests cover family validation, conflicting overrides, protocol/format
omission, IPv6 template conflicts, ShadowTLS placement, literal normalization,
WireGuard scope and legacy output. The opt-in `TestIPVersionClientDial` uses
`BOSUN_TEST_MIHOMO_BIN` and `BOSUN_TEST_SINGBOX_BIN` to launch isolated clients
against local A/AAAA DNS and HTTP proxy fixtures. It checks strict-family
connection/failure and dual fallback without changing system DNS or the user's
running proxy. This is a representative endpoint-dial test, not proof that all
protocols race or that a public server is reachable.
